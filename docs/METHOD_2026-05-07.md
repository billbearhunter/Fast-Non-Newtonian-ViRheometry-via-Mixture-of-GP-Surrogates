## 1. Overview

We recover the Herschel-Bulkley parameters
**θ = (n, η, σ_y)** [Herschel & Bulkley 1926] of a non-Newtonian fluid
from **S ≥ 2** release-and-spread camera experiments
[Hamamichi et al. 2023]. The default workflow uses S=2 (one
user-chosen setup plus the Hamamichi-orthogonal proposal); S=3 is
supported with no algorithmic change. The pipeline is a four-stage
Bayesian inverse:

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│ y_obs from      │ →  │ Hierarchical    │ →  │ Type-II ML      │ →  │ θ̂ + 95 % CI    │
│ camera          │    │ MoGP-rBCM       │    │ inverse via     │    │ + dispersion    │
│ (8 frames × 2   │    │ surrogate       │    │ batched 5-      │    │ (Bayes-honest   │
│  setups)        │    │ (forward model) │    │ restart CMA-ES  │    │  UQ output)     │
└─────────────────┘    └─────────────────┘    └─────────────────┘    └─────────────────┘
```

The mixture-of-Gaussian-process surrogate
[Tresp 2000; Deisenroth & Ng 2015; Rasmussen & Williams 2006] replaces
the prohibitively slow Material Point Method (MPM) [Sulsky et al. 1994]
forward simulation with hierarchical GP experts; CMA-ES
[Hansen & Ostermeier 2001; Hansen 2016] performs the inverse at
~30 ms / forward call.

## 2. Experimental observation

### 2.1 Setup geometry

A rectangular reservoir with width *W* (cm) and height *H* (cm) is filled
with the test fluid (density ρ).  At *t = 0* the front gate is released;
the fluid spreads forward under gravity.  Eight evenly-spaced frames
(*t = t₁ … t₈*) are captured by a calibrated side-view camera.  The
release-and-spread protocol follows Hamamichi et al. [2023].

### 2.2 y_obs vector (**new observation modality, our contribution**)

For each frame *i*, the front-most flow distance *y_i* (cm) is extracted
by silhouette segmentation + camera back-projection to the ground plane.
The eight cm-scale distances form **y_obs ∈ ℝ⁸**, used as the
likelihood's data vector.

> **Difference from [Hamamichi et al. 2023]**: Hamamichi's per-frame
> "observation" is the binary-XOR pixel-difference fraction between
> binarised reference and rendered silhouettes (their
> `GLRender3d/main.cpp:280-295`: `cv::bitwise_xor` then
> `(double)sumdiv/(width*height)`). Their final loss is
> `np.mean()` of the 8 dimensionless scalars. We replace this with a
> cm-scale flow-front distance per frame so each output dimension can
> be a GP regression target with physical units, can be compared with
> the analytical Poiseuille profile, and aligns with rheometer data.

**Implementation:** `Calibration/extract_flow_distance.py`,
`Calibration/build_y_obs.py`.

### 2.3 Multi-setup design (default S=2)

Each material is observed at **S ≥ 2 distinct (W, H) pairs**. Setup 1
is user-chosen; Setup 2 is the analytical Hessian-orthogonal proposal
(§7) inherited verbatim from [Hamamichi et al. 2023]. Choosing
complementary setups maximises Fisher information. S = 3 requires no
algorithmic change (the user adds a third geometry); the
multi-setup table in RESULTS reports σ_y relative error dropping by
roughly 4× from S=1 to S=3.

> **Attribution**: the multi-setup design philosophy and the
> Hessian-orthogonal proposer are inherited from [Hamamichi et al. 2023] and
> are not contributions of this paper. Our contribution is making
> the joint (not sequential) solve practical at tens of seconds per
> material rather than several hours per setup × N.

## 3. Capture and calibration pipeline

> **Our contribution (item 5 in §1)**: a single-invocation Python
> pipeline (`Calibration/prepare_configs.py`) that replaces the manual
> four-tool chain (Premier Pro + fSpy + Blender + Photoshop) used in
> [Hamamichi et al. 2023]. Each algorithmic stage below is a standard
> computer-vision primitive; the contribution is making the chain
> robust and operator-light so a single experiment goes raw video →
> $\mathbf{y}_{\text{obs}}$ in ~3 user clicks instead of an hour of
> manual editing.
>
> Detailed math + per-step references are in
> [`Calibration/MATH.md`](../Calibration/MATH.md); this section gives
> the structural overview for the paper narrative.

### 3.1 Pipeline overview

```
input:  video.mov (24 fps) + background.JPG + settings.xml
                                                ↓
  (1) frame extraction         dam-break detection; sample
                                config_00..config_08 at fixed cadence
                                                ↓
  (2) camera intrinsics         ChArUco-board calibration on background
                                → K, distortion d
                                                ↓
  (3) camera extrinsics         ChArUco prior + chamfer + IoU edge
                                refinement against config_00 cube
                                                ↓
  (4) silhouette segmentation   HSV threshold + ROI + morphology
                                → 8 binary masks
                                                ↓
  (5) flow-front back-          back-project front-most fluid pixel
      projection                via (K, R, t) to ground plane z=0
                                                ↓
output: 8 binary masks (config_*.png)
        camera_params.xml (K, d, R, t)
        y_obs ∈ ℝ⁸ (cm)
```

### 3.2 Frame extraction

Frame cadence (8 frames at 24 fps after the dam-break event) is
inherited from [Hamamichi et al. 2023]. Our automation: motion-based
dam-break event detection scrubs the video, proposes a $t = 0$
candidate, then the user confirms via GUI (one click in a typical
session). Frame indices are computed from $t_0 + i / \text{fps}$ and
read via VFR-safe `ffprobe` timestamp seek for non-CFR mp4 inputs.

### 3.3 Camera calibration (intrinsics + extrinsics)

#### 3.3.1 Intrinsics: ChArUco-board fit

ChArUco = ArUco-marker-embedded chessboard; sub-pixel corner detection
[Garrido-Jurado et al. 2014, 2016] gives unambiguous correspondence
even under partial occlusion. Camera intrinsics $K$ (focal length,
principal point) and 5-parameter Brown distortion $\boldsymbol{d}$
are fitted by Nelder–Mead [Nelder & Mead 1965] minimising reprojection
error against the pinhole model [Hartley & Zisserman 2003] applied to
the detected ChArUco corners on the background frame.

#### 3.3.2 Extrinsics: edge refinement

Initial pose $(R_0, \boldsymbol{t}_0)$ from the ChArUco intrinsics fit;
we then refine $(R, \boldsymbol{t})$ (with $K$ fixed) by matching the
rendered container-cube silhouette to the dam-break frame `config_00`:

**Phase 1** (smooth, L-BFGS-B [Byrd et al. 1995; Zhu et al. 1997]):
minimise the weighted chamfer distance

$$
\mathcal{L}_{\text{chamf}}(R, \boldsymbol{t}) =
\frac{1}{|\partial M_{\text{render}}|}
\sum_{\boldsymbol{p} \in \partial M_{\text{render}}}
d_{\text{EDT}}(\boldsymbol{p})
$$

where $\partial M_{\text{render}}$ are the rendered cube silhouette
edges and $d_{\text{EDT}}$ is the Euclidean distance transform
[Maurer et al. 2003] of the Canny edges [Canny 1986] of `config_00`.
Bilinear sampling of $d_{\text{EDT}}$ keeps the objective smooth
enough for L-BFGS-B.

**Phase 2** (non-smooth, Nelder–Mead): maximise pixel-IoU
[Jaccard 1912] between rendered and detected silhouettes. Rotation
parametrised by the Rodrigues exponential map
[Hartley & Zisserman 2003, §A6.6]. Safety clamps on
$\|\Delta R\|$ and $\|\Delta \boldsymbol{t}\|$ from the ChArUco prior
guard against local minima.

### 3.4 Silhouette segmentation

For each captured frame the binary fluid mask $M_i$ is produced by:

1. HSV colour thresholding with per-material thresholds.
2. ROI polygon mask drawn once on `config_08` (most-spread frame),
   excluding apparatus shadows and reflections.
3. Morphological closing then opening for noise removal
   [Gonzalez & Woods 2018, Ch. 9].
4. Largest-connected-component selection.

### 3.5 Flow-front back-projection (y_obs definition)

For each binary mask $M_i$, identify the front-most fluid pixel along
the flow direction $\boldsymbol{e}_{\text{flow}}$:

$$
(u^\star_i, v^\star_i) \;=\; \arg\max_{(u,v) \in M_i} \,\langle (u, v),\, \boldsymbol{e}_{\text{flow}} \rangle
$$

Back-project through the calibrated camera $(K, R, \boldsymbol{t})$
to the ground plane $z = 0$:

$$
(X_i, Y_i, 0) \;=\; \pi^{-1}_{(K, R, \boldsymbol{t}),\, z=0} (u^\star_i, v^\star_i)
$$

The cm-scale flow distance from the gate baseline along
$\boldsymbol{e}_{\text{flow}}$ is $y_i$. The 8 distances form
$\mathbf{y}_{\text{obs}} \in \mathbb{R}^8$ (whose role in the
likelihood is described in §2.2 and §5.1).

### 3.6 Implementation

| Stage | Module |
|---|---|
| Pipeline driver | `Calibration/prepare_configs.py` |
| ChArUco intrinsics + edge-refinement extrinsics | `Calibration/pipeline.py` (math + refs in `Calibration/MATH.md`) |

## 4. Forward surrogate: hierarchical MoGP-rBCM

### 4.1 Theory

The MPM forward map *θ → y_obs* is too slow (≳ 35 h/material) for
on-line inverse, so we approximate it by a hierarchical mixture of
Gaussian-process experts [Rasmussen & Williams 2006, Ch. 5].  Each
expert is an exact GP regressor with Matern 2.5 ARD kernel
[Stein 1999; Neal 1996].

For tractability we partition the input space *(W, H, n, log η, log σ_y)*
into ~25 disjoint geometric bins (gids) [step L1] and within each gid
into ~24-66 sub-experts via K-means clustering [MacQueen 1967] of a
PCA [Pearson 1901; Hotelling 1933] embedding of (shape + length)
features [step L2-L3].  The robust Bayesian Committee Machine
[Tresp 2000; Deisenroth & Ng 2015] formulation lets one query route to
ONE active expert without joint variance aggregation, sacrificing
inter-expert smoothness for forward speed.

### 4.2 Three-layer routing (math)

Given a query *(W, H, **y**)* where **y** = (y₁, …, y₈) ∈ ℝ⁸ is the
flow-front-distance observation:

$$
\begin{aligned}
\text{L1 (geometric):} \quad &
g \;=\; \arg\min_{g \in \mathcal{G}} \,\| (W, H) - (W_g, H_g) \|
\\[2pt]
\text{L2 (cluster):} \quad &
c \;=\; \arg\min_{c} \, \| \boldsymbol{\phi}(\mathbf{y}) - \boldsymbol{\mu}_c \|^2,\quad
\boldsymbol{\phi}(\mathbf{y}) = \big( \lambda \log y_8,\, \pi_1,\, \pi_2,\, \pi_3 \big)
\\[2pt]
& \pi_j = \langle \mathbf{e}_j,\, \boldsymbol{s}(\mathbf{y}) \rangle,\quad
s_i(\mathbf{y}) = \frac{y_{i+1} - y_1}{y_8 - y_1}\ \text{for } i=1,\ldots,7
\\[2pt]
\text{L3 (sub-expert):} \quad &
k^\star \;=\; \arg\min_{k} \, \frac{|y_8 - \mu_{8,k}|}{\sigma_{8,k}}
\quad \text{(1-D Bayes evidence; see §4.3)}
\end{aligned}
$$

where:
- $\mathcal{G}$ is the discrete set of training geometric bins (the
  *gids*), and L1 picks the geometric bin closest to the query (W, H).
- $\boldsymbol{\phi}(\mathbf{y}) \in \mathbb{R}^4$ is the cluster
  feature: log of final flow distance scaled by $\lambda = 5$
  (relative length-vs-shape weight) plus the first three principal
  components $\pi_j$ of the normalised shape vector $\boldsymbol{s}$.
- $\boldsymbol{\mu}_c$ are pre-computed cluster centroids in the L2
  feature space, and $\boldsymbol{e}_j$ are pre-computed PCA loadings.
- $\mu_{8,k}, \sigma_{8,k}$ are the empirical mean/std of training
  $y_8$ values in candidate sub-expert $k$.

### 4.3 L3 motivation: 1-D Bayes model selection on the final flow distance

After L1+L2 fix the geometric and shape regime, sub-experts within a
cluster differ primarily in their σ_y range. Let
$y_{8,k}^{(1)},\ldots, y_{8,k}^{(N_k)}$ denote the training final flow
distances ($i = 8$) inside candidate sub-expert $k$, and approximate
their distribution as Gaussian $\mathcal{N}(\mu_{8,k}, \sigma_{8,k}^2)$.
The negative log marginal likelihood of the observed $y_8$ under
sub-expert $k$ is, up to additive constants
[Murphy 2012, §5.3; MacKay 2003, Ch. 28]:

$$
-\log p(y_8 \mid k)
\;\approx\; \frac{(y_8 - \mu_{8,k})^2}{2 \sigma_{8,k}^2} + \tfrac12 \log \sigma_{8,k}^2
$$

Choosing $k^\star = \arg\min_k$ of the right-hand side is **standard
Bayes model selection on the marginal evidence** of the final flow
distance — a 1-D special case of the general Bayesian model-evidence
ratio. No GP forward call is required at routing time; only the
pre-computed empirical $(\mu_{8,k}, \sigma_{8,k}^2)$ statistics.

### 4.4 Per-sub ExactGP

Each sub holds 8 independent ExactGP regressors (one per frame
*i = 1…8*) with Matern 2.5 ARD kernel [Stein 1999] over the 5-D
input *z_5 = (n, log η, log σ_y, W, H)* (after standardisation).
Hyperparameters are learnt by maximum marginal likelihood
(Type-II MLE [Rasmussen & Williams 2006, §5.4.1]) via Adam
[Kingma & Ba 2015] for ≤ 200 iterations.

**Implementation:** `surrogate/experts.py:ExactExpert.fit`.

### 4.5 Training data

Per sub: *N ∈ [200, 1000]* MPM simulations sampled from a Latin-hypercube
[McKay et al. 1979] grid over θ-space, with manual densification in
σ_y-degenerate regions where early per-sub fits showed large residual.
We use the MLS-MPM variant of MPM [Hu et al. 2018] for forward simulation.
(Principled active-learning infill [Settles 2009] is listed as future
work in DISCUSSION §8, not implemented in the current pipeline.)

**Implementation:** `surrogate/partition_yshape.py` (training-data
partitioner), `scripts/partition_flat_kmeans.py` (production v2
partition), `surrogate/train_yshape_subs.py` (training loop).

### 4.6 Post-hoc GP variance calibration

Per-sub scalar *c_k = √(MSE_val / mean σ²_GP,val)* computed from a
random 90/10 hold-out of the sub's own training data.  At inference,
calibrated std *σ_eff = c_k · σ_GP*.  The calibration follows the
deep-learning calibration literature [Kuleshov et al. 2018], specialised
to per-sub scalars to keep the model lightweight.  **In production we
disable c_k by default** (see §5.3 for the rationale).

**Implementation:** `scripts/calibrate_subs_holdout.py`.

### 4.7 Production model state

Bank: `Models/yshape_mogp_production/state_gid_{0..24}/`.  Each gid carries
`state.pkl` (partition meta), `sub_assignments.csv` (training-point →
sub mapping), and `experts/sub_NNNN.pt` (per-sub state_dict + X_phys +
Y_phys + calib_scale).

## 5. Type-II ML inverse: GP-aware likelihood

### 5.1 Theory: heteroscedastic Gaussian likelihood + Occam factor

We assume a Gaussian observation model with state-dependent variance
[Rasmussen & Williams 2006, §5.5; Murphy 2012, §15.2.6]:

$$
\log y_{\text{obs},i} = \log \hat{y}_i(\theta) + \varepsilon_i + \delta_i,\quad
\varepsilon_i \sim \mathcal{N}\!\big(0, \,(\sigma_{\text{GP},i}/\hat{y}_i)^2\big),\ 
\delta_i \sim \mathcal{N}\!\big(0,\,\sigma_{\text{obs,log}}^2\big)
$$

where ε is GP epistemic uncertainty (the GP's predictive std propagated
via the delta method to log-y space) and δ is a measurement-noise
floor.  Convolution gives:

$$
\sigma_i^2(\theta) = \big(\sigma_{\text{GP},i}(\theta)/\hat{y}_i(\theta)\big)^2 + \sigma_{\text{obs,log}}^2
$$

The negative log marginal likelihood — also called Type-II ML or
empirical Bayes loss [Rasmussen & Williams 2006, §5.4.1; Bishop 2006,
§3.5] — is, per frame:

$$
-\log p(y_{\text{obs},i} \mid \theta) \;=\; \frac{r_i^2(\theta)}{2 \sigma_i^2(\theta)} + \tfrac12 \log \sigma_i^2(\theta) + \text{const}
$$

The first term is squared-error weighted by precision (Mahalanobis-like
distance); the second is the **Occam factor** [MacKay 2003, Ch. 28]
that penalises high-uncertainty hypotheses.  Without the Occam factor
the optimiser would game the loss by drifting θ into regions of large
σ_GP (hence small precision) where any residual is "explained" by
uncertainty.

### 5.2 Frame-weighted Type-II ML loss (full form)

Including frame importance weights and a soft bbox constraint:

$$
\ell(\theta) \;=\; \frac{1}{n_f}\sum_{i=1}^{n_f}\Bigg[
\underbrace{\frac{\alpha_i^2 \, r_i^2(\theta)}{2\,\sigma_i^2(\theta)}}_{\text{Mahalanobis}} +
\underbrace{\tfrac12 \log \sigma_i^2(\theta)}_{\text{Occam factor}}
\Bigg] + w_{\text{sup}}\,\Phi_{\text{sup}}(\theta)
$$

where:
- $r_i(\theta) = \log \hat{y}_i(\theta) - \log y_{\text{obs},i}$ is
  the per-frame log-residual.
- $\boldsymbol{\alpha} = (\alpha_1, \ldots, \alpha_8) =
  (0.2, 0.2, 0.35, 0.5, 0.8, 1.0, 1.4, 2.0)$ is an **empirical
  frame schedule** that progressively emphasises late frames; chosen
  to absorb the real–sim gap (early frames are in the gate-release
  transient where rendered cube silhouette and captured fluid
  silhouette disagree most: gate motion, release-timing jitter,
  free-surface effects unmodelled by the MPM forward; late frames
  have settled into the steady spread regime where the surrogate
  matches reality cleanly).
- $\Phi_{\text{sup}}(\theta) \ge 0$ is a soft-clamp penalty that keeps
  θ inside the routed sub's training bounding box; $w_{\text{sup}} > 0$
  is its weight.

This is **standard Type-II ML / Empirical Bayes** — zero free
regularisation hyperparameters.

**Implementation:** `Optimization/libs/selector.py:_setup_loss_gp_aware_np`
(per-frame loss), `inverse_single_setup` and `inverse_joint_setup`
(loss aggregation across frames, members, setups).

### 5.3 Production hyperparameter defaults

```
shape_gp_noise_log_floor   = 0.20      (σ_obs_log)
shape_disable_calib        = True      (c_k disabled, σ_eff = σ_GP)
```

**Motivation**: with small noise floors (e.g. 0.05) and active
calibration (e.g. c_k ~ 0.5 for some subs), σ²(θ) varies sharply over θ,
making the Occam factor ½ log σ²(θ) dominate the loss.  CMA-ES then
drifts toward GP-training-dense regions (where σ_GP is small), which
are not generally the rheometer truth.  Empirically (see RESULTS), the
0.20 floor + disabled calib is the single setting that recovers σ_y to
within 0.4 % on Chuno (low-σ_y) AND 12 % on Okonomiyaki (high-σ_y).
Lower floors + calib give Chuno σ_y +6.4 % AND Okonomi (n, η)
catastrophically off the HB ridge.

Backward compatibility: pass `--shape-gp-noise-log-floor 0.05
--no-shape-disable-calib` to recover pre-2026-05-07 behaviour.

### 5.4 Theory: joint multi-setup likelihood

The S setups *s = 1..S* are conditionally independent given θ
(separate experiments on the same material), so by the product rule
[Murphy 2012, §2.2]:

$$
-\log p(y_1, \ldots, y_S \mid \theta) \;=\; \sum_{s=1}^{S} -\log p(y_s \mid \theta) \;=\; \sum_{s=1}^{S} \ell_s(\theta)
$$

The **sum** (not average) of single-setup losses is the Bayes-correct
form — preserves the joint Hessian rank for honest multi-data-source
CI. Production default S=2; we also report S=1 and S=3 (see RESULTS).

### 5.5 Implementation: joint loss

Practical form (S setups):

$$
\ell_{\text{joint}}(\theta) = \sum_{s=1}^{S} \ell_s(\theta) + w_{\text{sup}} \cdot \tfrac{1}{S} \sum_{s=1}^{S} \text{sup}_s(\theta)
$$

**Implementation:** `Optimization/libs/selector.py:inverse_joint_setup`.
The current top-level CLI `Optimization.estimate_joint_setup` accepts
two setup paths; extension to S>2 only requires extending that
driver — the core likelihood is already in sum form.

### 5.6 Theory: K > 1 ensemble (logsumexp mixture marginal)

When top-*K* > 1 sub-experts are routed, the loss across ensemble
members is the mixture marginal NLL [Murphy 2012, §11.4]:

$$
-\log \sum_m \pi_m \, p_m(y \mid \theta)
\;=\; -\text{logsumexp}_m \big[\log \pi_m + \log p_m(y \mid \theta)\big]
\;=\; -\text{logsumexp}_m \big[\log \pi_m - \ell_m(\theta) \cdot n_f\big]
$$

This is Bayes-correct mixture marginalisation.  K = 1 collapses to
single NLL identically, so the production path (K = 1) is unchanged.

**Implementation:** `Optimization/libs/selector.py:_setup_nll_batched`.

## 6. CMA-ES with batched per-generation evaluation

### 6.1 Theory: CMA-ES

CMA-ES [Hansen & Ostermeier 2001; Hansen 2016] is a derivative-free
evolutionary optimiser that adapts a multivariate normal sampling
distribution to the loss landscape, suitable for the non-convex,
non-smooth Type-II ML loss surface induced by the surrogate.  We use
the standard `(μ_W, λ)`-CMA with rank-μ + rank-1 covariance updates;
hyperparameters: popsize λ = 12, max iterations = 30, σ₀ = 0.25 in
z-space.

**Implementation:** the `cma` Python library
[Hansen et al., https://github.com/CMA-ES/pycma], called from
`Optimization/libs/selector.py:_run_cma`.

### 6.2 Multi-start with dispersion diagnostic

We run *N_restarts = 5* independent CMA-ES with seeds
*(7 + sub_a · 100 + sub_b) + {0, 100, 200, 300, 400}*; report the
lowest-loss θ̂ and the **standard deviation across restarts** as a
truth-blind ridge-degeneracy diagnostic.  Multi-start CMA is a
well-known guard against local minima [Auger & Hansen 2005].

```
σ_y dispersion < 5 %  → unique basin, 1-restart sufficient
                  > 20 % → multi-basin (e.g. HB ridge), multi-restart needed
```

### 6.3 Theory: amortising launch overhead via batched eval

Each CMA-ES generation evaluates the loss at *λ = 12* candidate z's.
Naive implementation makes 12 sequential GP forward calls → 12 × CUDA
launch overhead (~37 ms each).  Batched evaluation makes ONE call with
all 12 z's, leveraging the GP's natural support for batched test
inputs [Rasmussen & Williams 2006, §2.7].  Loss aggregation (Mahalanobis
+ Occam + logsumexp + sup penalty) is pure CPU numpy, performed
per-z after the single GPU call.

### 6.4 Implementation: batched eval

The loss function accepts either a single z (shape (3,)) or a batch
(shape (P, 3)); returns scalar or P-vector correspondingly.  CMA's
`es.ask()` returns a list of λ z's, passed in one call to the loss.
The Hessian CI computation (§8) calls the loss with single z and gets
scalar — backward compat preserved.

Empirical wall-time speedup: 8-13× on joint inverse; see Results §4.

**Implementation:** `Optimization/libs/selector.py:_run_cma`,
`inverse_single_setup:loss`, `inverse_joint_setup:_setup_nll_batched`.

## 7. Active next-setup proposal (Hamamichi-orthogonal, verbatim port)

> **Attribution**: this section describes the proposer **inherited
> verbatim** from [Hamamichi et al. 2023];
> `Optimization/libs/mechanism.py` is a line-for-line port of their
> closed-form Hessian + grid search. This is not a method
> contribution of the present paper; we only invoke it inside the
> production pipeline.

### 7.1 Theory: Fisher-information orthogonality

Following Hamamichi et al. [2023], we choose the next setup to
maximise the **joint Fisher information** of the multi-setup
likelihood, equivalently to align the principal uncertainty
directions of the existing setups with the candidate direction so
they constrain orthogonal directions in θ-space [Lehmann & Casella
1998, §6]. Production default invokes the proposer on setup-1 to
suggest setup-2; for S=3 the same proposer is invoked on the
joint (setup-1, setup-2) Hessian to suggest setup-3.

For HB rheology under Poiseuille flow, the Fisher matrix has a
closed-form expression in (η, n, σ_y) at any candidate (W, H), allowing
candidate-grid search without any forward simulation.

### 7.2 Procedure

For each existing observed setup $s_i$ (parametrised by pressure $P_i$
and length scale $L_i$ in Hamamichi's Poiseuille reduction):

$$
H_i = H_{\text{HB}}(\hat{m},\, P_i,\, L_i),\qquad
\boldsymbol{q}_i = \text{principal eigenvector of } H_i
$$

where $H_{\text{HB}}$ is the closed-form Fisher / Hessian for the HB
parameter triple under Poiseuille channel flow [Hamamichi et al. 2023]
and $\boldsymbol{q}_i$ is the maximum-uncertainty direction in
$\theta$-space.

For each candidate $(W, H)$ on a 0.5-cm grid over
$[2, 7]\times[2, 7]$ cm, compute the analogous $H'$, $\boldsymbol{q}'$,
and select the geometry that minimises the squared projection of the
candidate eigenvector onto the existing ones (the orthogonality
criterion):

$$
(W^\star, H^\star) \;=\; \arg\min_{(W,H)} \, \sum_i \big(\boldsymbol{q}_i \cdot \boldsymbol{q}'(W, H)\big)^2
$$

### 7.3 Implementation

`Optimization/libs/mechanism.py` — verbatim port of Hamamichi
et al. [2023]'s analytical proposer (`single_hessian` for the closed-form
Hessian, `propose_next_setup` for the grid search).  CGS units
internally; (W, H) ∈ [2, 7] cm grid with 0.5 cm step in production.

Caveat: the analytical Hessian is computed under Poiseuille channel
flow, an approximation to our gravity-driven release-and-spread
experiment.  See DISCUSSION §1.

## 8. Uncertainty quantification

### 8.1 Theory: Hessian Laplace approximation

At the converged θ̂, the Bayesian posterior is approximated by the
Laplace expansion [MacKay 2003, Ch. 27; Bishop 2006, §4.4]:

$$
p(\theta \mid y) \;\approx\; \mathcal{N}\big(\hat{\theta},\, H^{-1}\big),\quad H = \nabla^2 \ell(\hat{\theta})
$$

This is asymptotically exact for the Type-II ML estimator under
regularity conditions [Lehmann & Casella 1998, §6.4].  In our
finite-sample HB-ridge regime, the approximation is local but
sufficient for confidence-interval reporting.

The 95 % credible interval on each dim of z is z_best ± 1.96·√[H⁻¹]_{ii};
the (n, η, σ_y) CI follows by exp-link transform.

### 8.2 Implementation: numerical Hessian + identifiability flag

H is computed by central finite differences (3 diag + 3 off-diag, total
9 extra GP forward evals) at z_best with step
*h_i = 0.10 · z_scale_i*.  Eigenvalues below
*0.01 · max|eval|* are floored for numerical stability (avoids cov →
∞ when the data does not constrain a direction).

A per-dim **identifiability flag** is True iff the dimension's eigenvector
mass on floored eigenvalues is below 50 %; False = dimension is
effectively unidentified by the data.

**Implementation:** `Optimization/libs/selector.py:_hessian_ci`.

### 8.3 Multi-restart dispersion (truth-blind)

Computed across the 5 CMA-ES restarts:

$$
z_{\text{disp},j} \;=\; \mathrm{std}\big[z_{\text{best}}^{(k)} \big]_{k=1..5,\,j}
$$

Translates to physical-unit relative dispersion via exp-link.  Provides
a **basin-uniqueness check** that complements the local Hessian CI:
small dispersion = unique global optimum; large dispersion = multi-basin
loss landscape (e.g. HB ridge).

### 8.4 Combined (CI, dispersion) diagnostic

Both signals are truth-blind (no rheometer data needed) and together
give a rigorous identifiability report:

```
Narrow CI  + low dispersion  → identified, trustworthy point estimate
Narrow CI  + high dispersion → CI underestimates uncertainty (rare; investigate)
Wide CI    + low dispersion  → identification by routing-bbox geometry
                                (Hessian flat plateau)
Wide CI    + high dispersion → unidentified, report bracketed estimate
```

## 9. Production workflow

Single material, ~20 s wall-time on a single GPU:

```bash
# 1. Capture setup1 frames + camera_params.xml.  Extract y_obs.
python -m Calibration.extract_flow_distance --dir ref_<mat>_<H>_<W>_1
python -m Calibration.build_y_obs            --dir ref_<mat>_<H>_<W>_1

# 2. Setup1 inverse + propose setup2.  ~10 s.
python -m Optimization.estimate_first_setup \
    --state-root Models/yshape_mogp_production \
    -f ref_<mat>_<H>_<W>_1 --density <ρ> \
    --shape-cma-restarts 5 --shape-report-ci

# 3. Capture setup2 frames at the proposed (W*, H*).  Extract y_obs.

# 4. Joint inverse with setup1 warm-start.  ~10 s.
python -m Optimization.estimate_joint_setup \
    -f ref_<mat>_<H>_<W>_1 -s ref_<mat>_<H*>_<W*>_2 \
    --shape-warm-start-from-first \
    --shape-cma-restarts 5 --shape-report-ci
```

Output (`<dir>/theta_hat.json`):

```jsonc
{
  "theta_hat":      {"n": ..., "eta": ..., "sigma_y": ...},
  "theta_ci_95":    {"n": [lo, hi], "eta": [lo, hi], "sigma_y": [lo, hi]},
  "identifiable":   {"n": bool, "eta": bool, "sigma_y": bool},
  "z_dispersion":   [σ_n, σ_log_η, σ_log_σ_y]
}
```
