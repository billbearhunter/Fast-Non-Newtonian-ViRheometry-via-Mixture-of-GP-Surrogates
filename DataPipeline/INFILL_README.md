# Data Infill — Distributed Multi-Machine Plan

Goal: bring the 5D-uniform training pool from current ~21k usable points up to
**~100k uniform points** by running coordinated MLS-MPM sims on 3 worker
machines.

## Why

The 5D parameter space `(n, log eta, log sigma_y, W, H)` of the existing
training pool is severely non-uniform. See `docs/5D_DATA_DIAGNOSIS.md`.

```
Current state (B=4 grid, 1024 cells):
  total pool          : ~370,000 pts
  "uniform-extractable" (B=4, Q=100): ~33,900 pts (339 / 1024 cells)
  median fill / cell  : ~44 pts
  worst corner        : 0.04% of total = ~150 pts
                        (low-eta + low-sigma_y region — V1 paper "Carbonara"-class)

After Round 2 infill (this plan):
  target              : Q=100 per non-empty cell × 866 cells = 86,600 uniform pts
  + the original 21k uniform → ~100k usable
  remaining work      : 39,923 sims (~22 hours total compute @ 2s/sim)
  on 3 machines       : ~7-8 hours per machine
```

## Workflow

### On the master machine (this one)

```bash
# 1a. Generate the plan with EQUAL machine capacity:
python scripts/generate_cell_plan.py --B 4 --Q 100 --machines 3
# → ~7.4h per machine

# 1b. Strong master + 2 weaker workers (master is 3x faster):
python scripts/generate_cell_plan.py --B 4 --Q 100 --machines 3 --machine-weights 3,1,1
# → master takes 60% of compute (heaviest cells); all 3 finish in ~5.1h
# → master gets 318 cells × ~24k sims, workers each get 105 cells × ~8k sims
# Cell cost = deficit × particle_count(W,H), so master gets the
# big-box (high W, H) cells which are 4.8x more expensive per sim
# than small-box cells. Total wall time equalised across the cluster.

# 2. Sync data_infill/ folder (5 MB) to each worker — see SIMULATION_SETUP.md
```

### On each worker machine

See `docs/INFILL_PROTOCOL.md` for full setup. Quick version:

```bash
cd New_ViRheometry/pipeline_v10/data_infill
python scripts/run_worker.py \
    --machine-id <0|1|2> \
    --plan plan/cell_plan.csv \
    --out-dir outputs/machine<0|1|2>
```

The worker is **resumable** — if killed, just re-run with the same args.
It checks how many rows already exist for each cell and only generates
the remaining sims.

### When a fast worker finishes early (help master)

If, e.g., machine 1 finishes its assigned 8k sims in 5h while master is
still slogging through 18k+ sims, machine 1 can help by taking master's
**not-yet-started** cells. Master keeps its in-progress cells; no
duplication.

```bash
# Step 1: Generate a helper plan covering ONLY master's untouched cells
python scripts/regen_remaining_plan.py \
    --plan plan/cell_plan.csv \
    --done-csvs outputs/machine0/infill_machine0.csv \
                outputs/machine1/infill_machine1.csv \
                outputs/machine2/infill_machine2.csv \
    --include-machine-ids 0 \
    --skip-cells-touched-in outputs/machine0/infill_machine0.csv \
    --machines 1 \
    --out plan/cell_plan_machine1_helper.csv

# Step 2: machine 1 starts as a helper with the new plan + new out-dir
python scripts/run_worker.py --machine-id 0 \
    --plan plan/cell_plan_machine1_helper.csv \
    --out-dir outputs/machine1_helper
```

The flags:
- `--include-machine-ids 0`: only consider cells originally assigned to master
- `--skip-cells-touched-in <master.csv>`: reserve cells master has already started
- `--machines 1`: pack the remaining work onto a single helper

If both machine 1 and machine 2 finish, run again with `--machines 2`
and assign both of them to master's tail. Or run twice independently
(once for each helper).

### After all workers finish

```bash
# 1. Pull each worker's output CSV back to the master machine
#    (e.g. via scp or git LFS)

# 2. Merge into a combined infill pool
python scripts/merge_worker_outputs.py \
    --inputs outputs/machine0/infill_machine0.csv \
             outputs/machine1/infill_machine1.csv \
             outputs/machine2/infill_machine2.csv \
    --out final/infill_pool.csv

# 3. Regenerate the 5D-uniform splits with old + new combined
python scripts/merge_worker_outputs.py --regenerate-splits \
    --infill-csv final/infill_pool.csv \
    --B 4 --Q 100 \
    --out-dir final/uniform_b4q100_v2

# This produces:
#   final/uniform_b4q100_v2/train_uniform.csv
#   final/uniform_b4q100_v2/val_uniform.csv
#   final/uniform_b4q100_v2/test_uniform.csv
# Total ~100k pts, balanced 80/10/10 within each cell.
```

### Then re-train V10 with the new pool

```bash
python -m pipeline_v10.surrogate.partition_v10_yshape \
    --train-csv pipeline_v10/data_infill/final/uniform_b4q100_v2/train_uniform.csv \
    --val-csv   pipeline_v10/data_infill/final/uniform_b4q100_v2/val_uniform.csv \
    --out-bank  pipeline_v10/Models/v10_yshape_uniform_v2 \
    --k-len 5 --k-sh-max 5 --min-n-per-sub 80

python -m pipeline_v10.surrogate.merge_tiny_subs \
    --bank pipeline_v10/Models/v10_yshape_uniform_v2 --threshold 100

python -m pipeline_v10.Optimization.train_yshape_subs \
    --bank pipeline_v10/Models/v10_yshape_uniform_v2 --gids all
```

## Key invariants

- **Cell IDs are deterministic**: same B and same axis ranges → same cell IDs.
  As long as all workers + the master use the same `cell_plan.csv`, they
  agree on cell membership.
- **Workers are independent**: each machine handles disjoint cells. No
  collisions, no merge conflicts.
- **Resumable**: each worker reads its own output CSV on startup and skips
  cells that are already at quota.
- **No DB, no shared state**: the only coordination is the `cell_plan.csv`
  file (immutable after generation).

## Performance notes

- 1 sim ≈ 2s on a CUDA GPU (HeadlessSimulatorMLS, MLS-MPM)
- 1 worker doing ~13k sims ≈ 7-8 hours
- All 3 workers in parallel ≈ same wall time, 3× throughput
- Output CSV per worker grows to ~3-5 MB (compressed if you `gzip` it)

## Caveats

- **Empty-cell sims**: by default, only currently non-empty cells are infilled.
  Adding `--include-empty` to `generate_cell_plan.py` includes truly empty
  cells, but those may be physical regimes where the simulator fails or
  produces nonsense (e.g. extremely-low-eta water-like fluids). Start without
  `--include-empty`.
- **Test-set leakage**: the merged uniform pool re-shuffles old + new across
  train/val/test. The "test" partition is no longer the original held-out
  test set. If you need the original held-out test for unbiased evaluation,
  restore it from `pipeline_v10/data/synthetic_splits_v2/test_v10_v2.csv`.
